# 语境 → 表情 标注指南

本文件是「表情包插件 · 语境模型」训练语料的唯一标注标准。语料作者、训练、验收都以它为准；有分歧先问 Lead，不自行改口径。

## 1. 任务定义

输入：一段**对话语境**（最近 1–3 轮；可以只有一句用户消息，也可以是多轮片段）。
输出：如果助手在这一轮要发一张表情包，最合适的那一张；若**不该发**表情，标 `none`。

- 标签集合 = 24 张表情（`data/assets.json` 的 `emotes[].name`，如 `05-困倦`）+ `none`。
- 标注的是「助手回复时**发的表情**」，不是「用户此刻的情绪」。用户说「我好累」→ 助手可以发 `05-困倦`；用户骂人→ 助手不该跟着骂，更可能是 `16-无语` 或 `none`。拿不准按第 4 节优先级。
- 表情是**回复的一部分**，语境里要能读出「该接什么情绪」。

## 2. 24 类语义 + 何时用 / 何时不用

`data/assets.json` 的 `tags` 是关键词线索，不是全部。下表是判决口径。

| 标签 | 含义 | 适用语境 | 不适用（易混） |
| --- | --- | --- | --- |
| `01-平静` | 中性、例行、稳 | 普通陈述、例行问答、平稳闲聊、没有明显情绪 | 有强情绪时不要拿它兜底 |
| `02-浅笑` | 礼貌微笑、轻松愉快 | 打招呼、轻松同意、被温和地夸、亲切回应 | 明显大笑（18）、害羞（15） |
| `03-侧目` | 审视、怀疑、斜眼 | 「真的假的」「你认真的吗」、发现矛盾、调侃式质疑 | 明确生气（13） |
| `04-皱眉` | 疑惑、担忧、为难 | 用户说奇怪/复杂/有点问题、需要确认、情况不妙 | 无语（16）、扶额（22） |
| `05-困倦` | 疲惫、困、熬夜 | 用户说累/困/加班/熬夜/早起 | 无聊（09/24）、晚安（17） |
| `06-惊讶` | 意外、震惊 | 突发消息、意外结果、突然提问、反转 | 思考（11） |
| `07-专注` | 认真、专注、干活 | 帮用户 debug/写代码/处理复杂任务、认真分析 | 轻松闲聊（08） |
| `08-喝茶` | 悠闲、吃瓜、看戏 | 闲聊、八卦、看别人热闹、慢慢聊 | 严肃任务 |
| `09-打哈欠` | 无聊、等太久 | 用户说好无聊/在等/内容重复冗长 | 困倦（05） |
| `10-得意` | 骄傲、小成功 | 用户分享完成/成功/被认可、炫耀式报喜 | 害羞（15） |
| `11-思考` | 琢磨、疑问、权衡 | 用户提问题/求建议/两难取舍 | 惊讶（06） |
| `12-被叫到` | 被点名、立即响应 | 用户喊助手名字/叫它/测试它是否在线/催它出来 | 正式称呼后的常规提问 |
| `13-生气` | 生气、替用户不平 | 用户遭遇不公/被欺负/被骗、义愤 | 用户对自己发火（→16/22/none） |
| `14-落泪` | 难过、伤心、感动 | 用户倾诉失落/伤心/被感动、离别 | 只求安慰（19） |
| `15-害羞` | 被夸、不好意思 | 用户夸助手/表白/肉麻调戏 | 单纯道谢（23） |
| `16-无语` | 无语、无奈、吐槽 | 用户讲荒谬事、槽点、无力吐槽 | 扶额（22）、生气（13） |
| `17-睡着` | 晚安、睡觉 | 用户说晚安/要睡了/深夜收工/凌晨 | 只是困（05） |
| `18-大笑` | 哈哈大笑 | 用户讲笑话/玩梗/分享好笑的事/哈哈哈 | 礼貌微笑（02） |
| `19-抱猫` | 可爱、治愈、安慰 | 用户 emo 求安慰、说可爱的东西、需要抱抱 | 明确伤心痛哭（14） |
| `20-撑伞` | 保护、陪伴、挡雨 | 用户说下雨被淋、需要保护、一起扛过去 | 通用安慰（19） |
| `21-举牌` | 举牌、公告、强调 | 用户要通知/公告/看这里/活动信息/「划重点」 | 普通提示 |
| `22-扶额` | 头疼、无力 | 用户描述离谱操作/猪队友/离谱 bug/反复出问题 | 无语（16） |
| `23-比心` | 感谢、喜欢、加油 | 用户道谢/说喜欢/互相打气/「么么」 | 被夸（15） |
| `24-托腮` | 等待、发呆、围观 | 用户说慢慢来/在等答复/发呆/围观讨论 | 困（05） |
| `none` | 不该发任何表情 | 见第 3 节 | — |

## 3. `none` 的判定（约占 10%）

满足任一条就标 `none`：

1. **安全与敏感**：医疗/法律/财务建议、丧亲、自伤、暴力、性、未成年相关、政治敏感、隐私数据。宁可 `none`。
2. **故障与事务**：报错堆栈、订单/退款/账号问题、部署失败、需要看日志。
3. **无情绪的事务指令**：只做事、无氛围词，如「帮我把这段 JSON 格式化」「这个接口的参数是什么」。
4. **信息不足**：「嗯」「好」「在吗」这类极短、无法判断情绪的消息（但反复呼叫可能算 `12-被叫到`，见第 4 节）。
5. **正式投诉/强烈不满**：用户在严肃投诉、要求解释，回复应先解决问题，不发俏皮表情。

注意：`none` 不等于「负面」。负面情绪（累/难过/生气/无奈）大多有对应表情，别偷懒标 `none`。

## 4. 优先级与歧义裁定（必须严格执行，保证 4 位作者口径一致）

按顺序判断，命中即定：

1. 命中第 3 节任一条 → `none`。
2. 用户明确点名/呼叫助手（「小Q」「助手」「在吗」重复、催它）→ `12-被叫到`。
3. 明确道谢 / 明显表达喜欢或爱 / 互相打气 → `23-比心`；夸助手本身（「你好厉害」「你好可爱」）→ `15-害羞`。
4. 明确「晚安/去睡/收工」且时间语境夜晚 → `17-睡着`。
5. 明确悲伤/哭/失落/感动到想哭 → `14-落泪`；只是 emo 求安慰、想被抱抱 → `19-抱猫`。
6. 明确愤怒（第三方不公、被骗、被欺负）→ `13-生气`；对自己/助手发火、荒诞离谱 → `16-无语`；用户描述猪队友/离谱 bug → `22-扶额`。
7. 明确好笑/玩梗/哈哈哈 → `18-大笑`；礼貌轻笑/轻松愉快 → `02-浅笑`。
8. 明确「累/困/熬夜/加班」→ `05-困倦`；「无聊/在等/发呆」不困 → `09-打哈欠` 或 `24-托腮`（等具体答复用 24，泛泛无聊用 09）。
9. 明确下雨/被淋/需要保护 → `20-撑伞`。
10. 明确意外/震惊/突发 → `06-惊讶`；需要琢磨/求建议/两难 → `11-思考`。
11. 明确夸奖/表白/肉麻 → `15-害羞`。
12. 认真技术任务/复杂分析且带「认真/加班/刷题/debug」氛围 → `07-专注`；纯事务指令 → 第 3 节第 3 条 `none`。
13. 通知/公告/「划重点」→ `21-举牌`；八卦吃瓜/看戏 → `08-喝茶`；完成报喜 → `10-得意`；怀疑/「真的假的」→ `03-侧目`；疑惑/情况不妙 → `04-皱眉`。
14. 都没有明显信号、但语境可发可不发 → `01-平静`（中性稳）。
15. 一条数据只标一个标签，不写多标签、不写「都行」。

多轮语境：以**最后一轮用户消息**为主，前面的轮次只作为情绪/话题背景。

## 5. 数据格式（JSONL，一行一条）

```json
{"text": "用户：今天加班到十一点，眼睛都睁不开了", "label": "05-困倦", "source": "authored-a-1", "note": ""}
```

- `text`：必填，字符串，**不要换行符**。单轮：`用户：<一句话>` 或直接写用户原话（同批统一，默认带「用户：」前缀，30% 不带）。多轮：`用户：… ；助手：… ；用户：…`，最后一轮必须是用户。
- `label`：必填，必须是 `data/assets.json` 的 24 个 `name` 之一或 `none`。
- `source`：必填，`authored-<作者字母>-1`（如 `authored-a-1`）。
- `note`：可选，短备注（可为空字符串）。
- UTF-8，无 BOM，一行一条，文件末尾留一个换行。

## 6. 写作要求（决定模型质量）

1. **多样性优先于数量**：同一标签至少 10 种不同句式/场景，禁止「我好累」「我好困」这种换词不换句的机械模板。
2. **长度分布**：70% 为 8–40 字，20% 为 40–90 字，10% 为 90–160 字（长语境）。
3. **场景分布**：工作/学习、生活、情感、社交闲聊、技术排查、线上娱乐都要有；人称覆盖「我/你/他/我们」；情绪强度覆盖轻/中/强。
4. **可判别**：语境要能读出标签所需的信号；不要写纯中性句子硬塞 `18-大笑`。
5. **多轮**（每位作者约 10%）：考察上下文情绪延续/反转。
6. **不要出现**：真实人名/公司名/手机号/邮箱/地址、英文大段、emoji 堆砌、广告、政治敏感、色情、暴力细节。
7. **标签不随机化**：同一语境不要在不同批次给不同标签；拿不准回第 4 节。
8. 写完后自检：逐行 `json.loads`；各 label 数量必须等于分配数；完全重复 text 必须为 0。

## 7. 分工与交付（已按设备预算缩减）

| 作者 | 负责标签 | 数量 | 文件 |

| B | 07-专注、08-喝茶、09-打哈欠、10-得意、11-思考、12-被叫到 | 6×90 + 60 none = 600 | `authored-b-1.jsonl` |
| C | 13-生气、14-落泪、15-害羞、16-无语、17-睡着、18-大笑 | 6×90 + 60 none = 600 | `authored-c-1.jsonl` |
| D | 19-抱猫、20-撑伞、21-举牌、22-扶额、23-比心、24-托腮 | 6×90 + 60 none = 600 | `authored-d-1.jsonl` |

- 每个标签 90 条：80 条单轮 + 10 条多轮；`none` 60 条（50 单轮 + 10 多轮）。总计 2400 条（原计划 4000 条已缩减，设备只跑轻量模型）。
- 单文件 ≤ 620 行，可分 2–3 次写入（每次 ≤220 行追加）。
- 只写自己负责的标签；**不要读别人的 raw 文件、不要动代码/文档/资产**。
- 工作区会被并行会话清理：语料统一写到影子工作区 `/tmp/emote-build/train/data/raw/`（Lead 同步回仓库），并在自己 `/tmp` 留备份；**不要写仓库内的 train/**。
- 不要 git commit。

## 8. 反例（写了会被退回）

- ❌ `{"text":"我好困","label":"05-困倦"}` —— 单一模板，且 3 字太短。
- ❌ 把「谢谢」标成 `15-害羞` —— 应按第 4 节第 3 条标 `23-比心`。
- ❌ 把报错堆栈标成 `07-专注` —— 第 3 节第 2 条，应 `none`。
- ❌ 同一条多次出现在不同批次。
- ❌ 每条都写「用户：…」且句式都是「用户：我今天……」。
- ❌ 给「用户：我要自杀」标任何表情 —— 必须 `none`。

本语料为**合成标注**，不含任何真实用户聊天记录；后续如用真实数据需用户明确授权并去标识化。
